# AIGC 课程知识图谱 — 接口文档

> 本文档基于后端实际路由代码整理，覆盖基础能力与课程协作能力（含课程、成员权限、抽取任务、图谱编辑、课程问答、学习路径和用户资料接口）。旧版扁平接口继续保留用于兼容。
> 启动后端后也可访问 FastAPI 自动文档：`http://localhost:8000/docs`（Swagger）或 `http://localhost:8000/redoc`。

## 一、通用约定

| 项目 | 说明 |
| --- | --- |
| Base URL | `http://localhost:8000`（前端通过 `VITE_API_BASE` 覆盖） |
| 数据格式 | 请求/响应均为 JSON（文件上传除外，使用 `multipart/form-data`） |
| 认证方式 | 在请求头携带 `Authorization: Bearer <token>`，token 由 `/api/auth/login` 或 `/api/auth/register` 返回 |
| Token 有效期 | 7 天（HS256 签名，纯标准库实现） |
| 错误响应 | `{ "detail": "错误信息" }`，HTTP 状态码：400 参数错误 / 401 未认证 / 404 不存在 / 409 冲突 / 500 服务器错误 |

### 认证分类

- **必须登录**：`GET /api/auth/me`
- **可选登录**（带有效 token 记录到对应用户，不带则用 `default` 用户）：学习进度、自适应学习相关接口
- **无需登录**：文档管理、图谱、学习路径、问答、AIGC、健康检查

> 对标记为“可选登录”的接口，如果请求显式携带了无效或过期的 Bearer Token，服务会返回 401；只有完全不携带认证头时才会使用 `default` 用户。

## 三、认证模块（auth）

前缀：`/api/auth`

### 1. `POST /api/auth/register` — 注册

- **认证**：无
- **Body**

| 字段 | 类型 | 必填 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| username | string | 是 | 2-32 字符 | 用户名 |
| password | string | 是 | 6-64 字符 | 密码 |
| role | string | 否 | `teacher` / `student`，默认 `student` | 角色 |

**响应示例**

```json
{
  "token": "eyJhbGciOi...",
  "user": { "id": "9a8b7c...", "username": "alice", "role": "student" }
}
```

**错误**：409 用户名已存在

### 2. `POST /api/auth/login` — 登录

- **认证**：无
- **Body**：`{ "username": "alice", "password": "secret123" }`

**响应示例**

```json
{
  "token": "eyJhbGciOi...",
  "user": { "id": "9a8b7c...", "username": "alice", "role": "student" }
}
```

**错误**：401 用户名或密码错误

### 3. `GET /api/auth/me` — 获取当前用户

- **认证**：**必须登录**
- **响应**：`{ "id": "...", "username": "...", "role": "..." }`

## 四、课程与成员模块（courses）

课程接口以课程成员关系作为数据隔离边界。课程所有者和教师可以维护文档、抽取任务及图谱；学生可以读取课程图谱、提问和更新自己的学习进度。除课程列表和注册/登录外，课程接口都需要携带有效 Bearer Token。

### 1. 课程基本信息

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/courses` | 登录用户 | 返回自己拥有或加入的课程；未登录返回公开的 `default` 成员课程 |
| POST | `/api/courses` | 教师 | 创建课程并自动成为 owner |
| GET | `/api/courses/{course_id}` | 课程成员 | 获取课程详情 |
| PUT | `/api/courses/{course_id}` | owner / teacher | 更新名称和描述 |
| DELETE | `/api/courses/{course_id}` | owner | 删除课程及课程成员关系 |
| POST | `/api/courses/{course_id}/join` | 登录用户 | 幂等加入课程，返回 `{course, already_member}` |

### 2. 课程文档、抽取任务和结果

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/courses/{course_id}/documents` | 课程成员 | 只返回本课程文档 |
| POST | `/api/courses/{course_id}/documents/upload` | owner / teacher | 上传并同步解析；返回 `task_id`、文档 id、节点/关系数量 |
| POST | `/api/courses/{course_id}/documents/{document_id}/parse` | owner / teacher | 对已有文档重新抽取并创建任务记录 |
| GET | `/api/documents/tasks/{task_id}` | 课程成员 | 查询抽取任务状态 |
| POST | `/api/courses/{course_id}/extraction/trigger` | owner / teacher | 重新抽取课程全部文档；可用 `document_id` 查询参数只处理一份文档 |
| GET | `/api/courses/{course_id}/extraction/result` | owner / teacher | 获取本课程当前图谱作为审核结果 |
| DELETE | `/api/courses/{course_id}/documents/{document_id}` | owner / teacher | 删除文档及该文档产生的节点/关系 |

任务状态为 `pending`、`done` 或 `error`。课程上传生成的节点和关系 id 带有课程命名空间，避免两个课程上传相同文件时互相覆盖。

### 3. 课程图谱编辑与导出

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/courses/{course_id}/graph` | 课程成员 | 支持 `category` 和 `q` 过滤 |
| GET | `/api/courses/{course_id}/nodes/{node_id}` | 课程成员 | 获取单个节点 |
| POST | `/api/courses/{course_id}/nodes` | owner / teacher | 新增或更新节点 |
| PUT | `/api/courses/{course_id}/nodes/{node_id}` | owner / teacher | 更新节点 |
| DELETE | `/api/courses/{course_id}/nodes/{node_id}` | owner / teacher | 删除节点及相连关系 |
| POST | `/api/courses/{course_id}/relations` | owner / teacher | 新增或更新关系；两端节点必须属于本课程 |
| DELETE | `/api/courses/{course_id}/relations/{relation_id}` | owner / teacher | 删除关系 |
| GET | `/api/courses/{course_id}/graph/export` | 课程成员 | `format=json` 返回 JSON，`format=graphml` 返回 GraphML |

## 五、课程问答、反馈和学习路径

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |

| GET | `/api/courses/{course_id}/qa/history` | 课程成员 | 学生只看到自己的历史；教师看到课程内全部历史，支持 `limit` |

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |

课程学习记录同时带有 `course_id`，不会混入其他课程的同名节点或进度。

## 七、文档管理模块（documents）

前缀：`/api/documents`

负责上传课程文档、解析文本、调用 LLM 抽取知识图谱并入库。支持 PDF / Word / PowerPoint / 纯文本解析。

### 1. `GET /api/documents` — 文档列表

- **认证**：无
- **响应**：`DocumentOut[]`，按创建时间倒序

```json
[
  {
    "id": 1,
    "filename": "高等数学教材.pdf",
    "content_type": "application/pdf",
    "size_bytes": 1048576,
    "extract_status": "done",
    "error_msg": null,
    "created_at": "2026-09-15T10:00:00"
  }
]
```

> `extract_status`：`pending` / `done` / `error`

### 2. `POST /api/documents/upload` — 上传并抽取知识图谱

- **认证**：无
- **Content-Type**：`multipart/form-data`
- **表单字段**：`file`（必填，上传文件）
- **说明**：同步执行 解析文本 → 抽取知识图谱 → 按 id upsert 写入 KGNode/KGRelation。解析失败仍会用离线 fallback 继续抽取。

**响应示例**

```json
{
  "document_id": 2,
  "extract_status": "done",
  "nodes_count": 26,
  "relations_count": 48,
  "error_msg": null
}
```

### 3. `GET /api/documents/{doc_id}` — 文档详情

- **认证**：无
- **路径参数**：`doc_id` (int)
- **响应**：`DocumentOut`
- **错误**：404 文档不存在

### 4. `DELETE /api/documents/{doc_id}` — 删除文档

- **认证**：无
- **说明**：同时删除该文档贡献的节点与关系，其他文档抽取的保留。
- **响应**：`{ "ok": true }`
- **错误**：404 文档不存在

## 八、知识图谱模块（graph）

前缀：`/api/graph`

提供图谱查询、分类统计、节点/关系增改、示例数据导入与清空。

### 1. `GET /api/graph` — 查询图谱

- **认证**：无
- **Query**

| 参数 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| category | string | 否 | 按类别过滤（如 `协议`、`算法`） |
| q | string | 否 | 按名称/描述关键词搜索 |

**响应**：`KnowledgeGraphOut`

```json
{
  "nodes": [
    {
      "id": "n5",
      "name": "TCP 协议",
      "category": "协议",
      "description": "面向连接的、可靠的传输层协议...",
      "difficulty": 4.0,
      "x": null,
      "y": null
    }
  ],
  "relations": [
    { "id": "r4", "source": "n3", "target": "n5", "type": "包含", "label": "传输层协议 TCP" }
  ]
}
```

### 2. `GET /api/graph/stats/categories` — 分类统计

- **认证**：无
- **响应**：`CategoryStat[]`，按数量降序

```json
[ { "category": "协议", "count": 12 }, { "category": "核心概念", "count": 5 } ]
```

### 3. `POST /api/graph/nodes` — 新增/更新节点

- **认证**：无
- **Body**：`KGNodeOut`（按 `id` upsert）

```json
{
  "id": "n99",
  "name": "QUIC 协议",
  "category": "协议",
  "description": "基于 UDP 的多路复用安全传输协议",
  "difficulty": 4.2,
  "x": null,
  "y": null
}
```

**响应**：写入后的 `KGNodeOut`

### 4. `POST /api/graph/relations` — 新增/更新关系

- **认证**：无
- **Body**：`KGRelationOut`（按 `id` upsert）

```json
{ "id": "r99", "source": "n3", "target": "n99", "type": "包含", "label": "传输层新协议" }
```

- **错误**：400 两端节点不存在（需先创建节点）

### 5. `POST /api/graph/seed-sample` — 写入示例图谱

- **认证**：无
- **说明**：写入一份完整的计算机网络示例图谱（26 个节点 + 48 条关系），方便前端「加载示例」按钮调用。
- **响应**：`KnowledgeGraphOut`（写入后的完整图谱）

### 6. `DELETE /api/graph/wipe` — 清空图谱

- **认证**：无
- **说明**：删除全部节点与关系（测试用）
- **响应**：`{ "ok": true }`

## 十、学习路径模块（learning-path）

前缀：`/api/learning-path`

以「先修」关系构成 DAG，拓扑排序生成个性化学习路径。

### `POST /api/learning-path/recommend` — 推荐学习路径

- **认证**：无
- **Body**

| 字段 | 类型 | 必填 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| user_id | string | 否 | `default` | 用户标识，用于读取掌握状态 |
| start_node_id | string | 否 | 无 | 指定起点，路径从此节点开始 |
| target_node_id | string | 否 | 无 | 指定终点，路径到此节点结束 |
| max_items | int | 否 | 30 | 最多返回步骤数 |
| prerequisite_relation_types | string[] | 否 | `["先修","前置","prerequisite","依赖"]` | 视作前置依赖的关系类型 |

**响应**：`LearningPathOut`

```json
{
  "steps": [
    {
      "node_id": "n1",
      "name": "计算机网络",
      "category": "基础概念",
      "description": "...",
      "mastered": false,
      "prerequisites": [],
      "reason": "基础入门知识点，无前置依赖，适合开始。"
    },
    {
      "node_id": "n5",
      "name": "TCP 协议",
      "category": "协议",
      "description": "...",
      "mastered": false,
      "prerequisites": ["n1", "n2"],
      "reason": "建议先掌握：OSI 七层模型。"
    }
  ],
  "total_steps": 26,
  "remaining": 14
}
```

- **说明**：图谱无先修边时退化为按难度升序 + 类别分组；存在环时贪心取最小度节点保证输出稳定。
- **错误**：400 知识图谱为空

## 十一、智能问答模块（qa）

前缀：`/api/qa`

基于知识图谱的简化版 RAG 问答：关键词检索 + 可选 LLM 生成。

### 1. `POST /api/qa/ask` — 提问

- **认证**：无
- **Body**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| question | string | 是 | 1-500 字符 |
| user_id | string | 否 | 默认 `default` |
| use_llm | boolean | 否 | `null` 自动：配置了 LLM key 就用，否则走关键词；`true` 强制 LLM；`false` 强制关键词 |

**响应**：`QAAnswer`

```json
{
  "answer": "TCP 通过三次握手建立连接...",
  "related_nodes": [
    { "id": "n5", "name": "TCP 协议", "category": "协议", "description": "...", "difficulty": 4.0, "x": null, "y": null }
  ],
  "used_llm": true
}
```

- **说明**：每次提问会记录一条历史到 `QARecord` 表。

### 2. `GET /api/qa/history` — 问答历史

- **认证**：无
- **Query**

| 参数 | 类型 | 默认 | 说明 |
| --- | --- | --- | --- |
| user_id | string | `default` | 用户标识 |
| limit | int | 20 | 返回条数 |

**响应**

```json
[
  {
    "id": 1,
    "question": "什么是三次握手？",
    "answer": "TCP 通过三次握手建立连接...",
    "used_llm": true,
    "related_node_ids": ["n5", "n14"],
    "created_at": "2026-09-15T10:05:00"
  }
]
```

## 十二、AIGC 模块（aigc）

前缀：`/api/aigc`

围绕主题调用大模型直接生成知识图谱、为单个知识点生成学习资源建议、搜索 B 站教学视频。

### 1. `POST /api/aigc/generate` — AIGC 生成知识图谱

- **认证**：无
- **Body**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| topic | string | 是 | 1-200 字符，课程主题（如「计算机网络」） |
| model | string | 否 | 覆盖默认模型 |

**说明**：调用大模型围绕主题生成知识图谱，按 id upsert 写入数据库并返回。

**响应**

```json
{
  "topic": "计算机网络",
  "nodes": [{ "id": "...", "name": "...", "category": "...", "description": "...", "difficulty": 3.5 }],
  "relations": [{ "id": "...", "source": "...", "target": "...", "type": "先修", "label": "..." }],
  "summary": "本主题涵盖...",
  "used_llm": true,
  "nodes_count": 30,
  "relations_count": 55
}
```

### 2. `POST /api/aigc/resources/suggest` — 学习资源建议

- **认证**：无
- **Body**

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| node_name | string | 是 | 1-200 字符，知识点名称 |
| category | string | 否 | 类别 |
| description | string | 否 | 描述 |
| model | string | 否 | 覆盖默认模型 |

**说明**：针对单个知识点调用大模型生成学习资源建议（书籍/文档/视频等），返回大模型原始结果。

### 3. `GET /api/aigc/bilibili-videos` — B 站教学视频搜索

- **认证**：无
- **Query**

| 参数 | 类型 | 必填 | 默认 | 约束 | 说明 |
| --- | --- | --- | --- | --- | --- |
| keyword | string | 是 | — | 1-100 字符 | 知识点名称 |
| limit | int | 否 | 8 | 1-20 | 返回条数 |

**说明**：调用 B 站 WBI 签名搜索接口，自动追加「讲解」后缀偏向教学类视频；过滤时长 < 2 分钟或标题含娱乐关键词的结果；WBI 签名失败时回退返回搜索页 URL。

**响应（成功）**

```json
{
  "videos": [
    {
      "bvid": "BV1xx411c7mD",
      "title": "TCP 三次握手讲解",
      "author": "技术博主",
      "play": 120000,
      "danmaku": 800,
      "favorites": 5000,
      "pic": "https://i0.hdslb.com/...",
      "duration": "12:30",
      "url": "https://www.bilibili.com/video/BV1xx411c7mD"
    }
  ],
  "ok": true,
  "keyword": "TCP"
}
```

**响应（失败回退）**

```json
{
  "videos": [],
  "ok": false,
  "error": "B站搜索接口返回异常",
  "fallback_url": "https://search.bilibili.com/all?keyword=TCP"
}
```

## 十三、自适应学习模块（adaptive-learning）

无统一前缀，接口直接挂在根路径下。需登录后记录到对应用户，未登录用 `default`。

### 1. `POST /api/quiz/submit` — 提交测试

- **认证**：可选
- **Body**

| 字段 | 类型 | 必填 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| node_id | string | 是 | 1-64 字符 | 知识点 id |
| correct_count | int | 是 | 0-100 | 答对题数 |
| total_count | int | 是 | 1-100 | 总题数 |

**说明**：计算正确率，**正确率 ≥ 67% 自动标记为已掌握**，同步更新 `UserProgress`。

**响应**：`QuizAttemptOut`

```json
{
  "id": 1,
  "node_id": "n5",
  "correct_count": 8,
  "total_count": 10,
  "accuracy": 80.0,
  "passed": true,
  "completed_at": "2026-09-15T10:10:00"
}
```

- **错误**：404 知识点不存在

### 2. `GET /api/learning/report` — 学习报告

- **认证**：可选
- **Query**

| 参数 | 类型 | 默认 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| recent_limit | int | 8 | 1-50 | 最近测试记录条数 |

**响应**：`LearningReportOut`

```json
{
  "user_id": "9a8b7c...",
  "learning_preference": "balanced",
  "total_nodes": 26,
  "mastered_nodes": 12,
  "mastery_rate": 46.15,
  "mastered_node_ids": ["n1", "n2", "n5"],
  "quiz_count": 18,
  "average_accuracy": 72.5,
  "weak_node_ids": ["n14", "n17"],
  "recent_attempts": [
    {
      "id": 18,
      "node_id": "n14",
      "correct_count": 3,
      "total_count": 10,
      "accuracy": 30.0,
      "passed": false,
      "completed_at": "2026-09-15T10:15:00"
    }
  ]
}
```

> `learning_preference`：`reinforce`（巩固优先）/ `balanced`（均衡推进）/ `challenge`（挑战进阶），默认 `balanced`

### 3. `GET /api/learning/recommendations` — 动态推荐

- **认证**：可选
- **Query**

| 参数 | 类型 | 默认 | 约束 | 说明 |
| --- | --- | --- | --- | --- |
| limit | int | 10 | 1-50 | 返回推荐数 |

**说明**：按 前置知识满足度 × 知识点难度 × 学习偏好 × 薄弱点 综合打分排序，跳过已掌握节点。打分逻辑：
- 基础分 = `ready_ratio × 55 + difficulty × 6`
- 薄弱知识点加 12 分
- 巩固偏好：薄弱 +30 / 支撑薄弱的 +20
- 挑战偏好：难度 ≥ 4 且前置满足一半 +14

**响应**：`LearningRecommendationOut[]`

```json
[
  {
    "node_id": "n14",
    "name": "三次握手",
    "category": "核心概念",
    "description": "TCP 建立连接的过程...",
    "importance": 4.2,
    "priority": 1,
    "prerequisites": ["n5"],
    "missing_prerequisites": [],
    "latest_accuracy": 30.0,
    "reason": "上次测试正确率 30% ，建议优先巩固"
  }
]
```

### 4. `PUT /api/learning/preference` — 设置学习偏好

- **认证**：可选
- **Body**：`{ "preference": "reinforce" }`

> `preference`：`reinforce` / `balanced` / `challenge`

- **错误**：422 不支持的学习偏好
- **响应**：更新后的 `LearningReportOut`（便于前端刷新报告）

## 附录：数据模型速查

### 节点 KGNode

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 节点唯一标识 |
| name | string | 名称 |
| category | string | 类别（基础概念/核心概念/协议/算法/设备/应用） |
| description | string | 描述 |
| difficulty | float | 难度 1-5 |
| x / y | float | 前端画布坐标（可选） |

### 关系 KGRelation

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 关系唯一标识 |
| source / target | string | 起止节点 id |
| type | string | 关系类型（先修/前置/包含/依赖/基于/...） |
| label | string | 关系标签说明 |

> **先修关系类**：`先修` / `前置` / `prerequisite` / `依赖`，用于学习路径 DAG 与自适应推荐。

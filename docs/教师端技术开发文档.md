## 1. 角色定位与权限边界

### 1.1 教师端用户画像
教师（`role = teacher`）是课程资源的创建者、审核者、发布者；不参与学习路径侧的"标记掌握"，但可**查看所有学生的掌握统计**。管理员（`admin`）拥有教师所有权限 + 用户管理，但本文档只描述教师角色，admin 侧差异仅在第 8 节补充。

### 1.2 RBAC 权限矩阵（严格对齐 §14 安全与规范）

| 能力 | 未登录 | 学生 | 教师 | admin |
|---|:-:|:-:|:-:|:-:|
| 登录 / 注册 / 找回 | ✔ | ✔ | ✔ | ✔ |
| 加入课程（course_code 加课） | | ✔ | | |
| 查看公开课程列表 | | ✔ | ✔ | ✔ |
| **创建课程 / 编辑课程元信息 / 删除课程** | | | ✔（owner） | ✔ |
| **上传课程文档 / 触发解析 / 删除文档** | | | ✔（owner） | ✔ |
| **触发知识抽取任务 / 查看抽取状态** | | | ✔（owner） | ✔ |
| **审核低置信度节点与关系** | | | ✔（owner） | ✔ |
| **图谱编辑（增删节点/关系、改属性）** | | | ✔（owner） | ✔ |
| 查看图谱、详情抽屉、邻居发现 | | ✔ | ✔ | ✔ |
| 导出图谱（JSON / PNG） | | ✔ | ✔ | ✔ |
| RAG 问答、查看问答历史 | | ✔ | ✔ | ✔ |
| **全体学生学习进度仪表盘** | | | ✔（owner） | ✔ |
| **生成邀请码 / 重置加课码** | | | ✔（owner） | ✔ |
| 用户管理（封禁、改角色） | | | | ✔ |

> 规则：课程维度的所有写操作（文档 / 抽取 / 编辑 / 进度统计）**必须**在前端先判断 `course.owner_id === auth.user.user_id`，后端再做一次二次校验（防止绕过前端）。

### 1.3 鉴权方案（对齐 §14 JWT 规范）
- 登录成功返回 `{access_token: "Bearer xxx", token_type: "bearer", expires_in: 86400, user: {...}}`
- 前端 `localStorage` 存 `access_token`，内存 Pinia 存 `user` 对象
- 每次请求用 Axios 请求拦截器自动加 `Authorization: Bearer <token>`
- 401：清 token → 跳 `/login` + 带上 `redirect` 参数；403：全局 Toast 提示"当前账号无权限执行此操作"

## 2. 信息架构与路由表

教师端布局采用**左侧侧边栏 + 顶栏 + 主内容区**。顶栏展示：当前课程切换器（下拉）、消息铃铛（抽取任务完成通知）、用户头像。

| 路径 | 页面组件 | 功能定位 | 路由级守卫 |
|---|---|---|---|
| `/login` | `views/LoginView.vue` | 邮箱 + 密码登录；注册入口；找回密码 | 仅未登录可访问 |
| `/register` | `views/RegisterView.vue` | 教师自助注册（role=teacher 可由种子审核开关控制） | 仅未登录 |
| `/courses` | `views/teacher/CourseListView.vue` | 课程卡片列表 + 创建课程抽屉 + 过滤（按创建时间 / 学生数） | `auth.role in (teacher,admin)` |
| `/courses/new` | `views/teacher/CourseCreateView.vue` | 三步向导：①元信息 ②上传首批文档 ③预览加课码 | 同左 |
| `/courses/:courseId/overview` | `views/teacher/CourseOverviewView.vue` | 课程仪表盘：节点数 / 关系数 / 学生数 / 掌握率 / 最近 7 天问答数 6 大 KPI + 最近抽取任务时间线 | 同左 + 课程访问者校验（owner 或被授权教师） |
| `/courses/:courseId/documents` | `views/teacher/DocumentManageView.vue` | 文档列表（含解析/抽取状态 Badge）、上传、重命名、重新解析、删除、任务详情抽屉 | 同左 + owner 校验 |
| `/courses/:courseId/extraction` | `views/teacher/ExtractionReviewView.vue` | **核心工作台**：待审核节点 / 待审核关系 两个数据表格 + 右侧图谱预览联动高亮 + 批量确认/删除/重新抽取 | 同左 + owner 校验 |
| `/courses/:courseId/graph-editor` | `views/teacher/GraphEditorView.vue` | AntV G6 编辑模式图谱：新增/删除/编辑节点/关系、拖拽定位、节点批量改类型、颜色、导出 | 同左 + owner 校验 |
| `/courses/:courseId/qa-admin` | `views/teacher/QAAdminView.vue` | 问答历史查询、反馈列表（"答案不准确/不完整"工单）、批量关闭 | 同左 + owner 校验 |
| `/courses/:courseId/students` | `views/teacher/StudentProgressView.vue` | 学生列表 + 单个学生进度热力图 + 班级掌握分布 + 薄弱知识点 Top10 榜单 + 导出 CSV | 同左 + owner 校验 |
| `/courses/:courseId/settings` | `views/teacher/CourseSettingsView.vue` | 元信息编辑、加课码重置、课程封面图上传、归档/发布开关、删除课程（二次确认） | 同左 + owner 校验 |

## 3. 页面详细设计

### 3.1 登录 / 注册
**功能清单**：邮箱格式即时校验、密码强度（8+位）、教师 vs 学生注册 Tab 切换（学生注册走学生端文档）、图形验证码（防止脚本批量注册）。  
**接口**：`POST /api/auth/login`、`POST /api/auth/register`、`GET /api/auth/me`（登录后自动拉）。  
**UI 要点**：品牌 Logo + 一句 Slogan「AI 构建知识图谱，让课程导航更聪明」；右侧一张手绘风格的插图（可选 AntV 随机节点点缀）。

### 3.2 课程列表 `/courses`
- 顶部操作区：`+ 新建课程` 主按钮、搜索框（按 name/description）、过滤器（"全部 / 我创建的 / 已归档"）。
- 卡片网格：每张卡片显示课程封面、名称、描述两行、节点数/关系数/学生数三个徽标、创建者、`编辑 / 删除 / 继续备课` 三个操作。
- 空状态：插画 + "还没有课程，点击右上角创建你的第一门课程吧"。

**接口**：`GET /api/courses`、`DELETE /api/courses/{id}`（二次确认）。

### 3.3 创建课程 `/courses/new` 三步向导
Step 1 元信息：`name`、`description`（富文本编辑器可选纯 textarea）、`course_code`（自动生成 8 位可修改、后端校验 UNIQUE）、封面上传。  
Step 2 文档上传：拖拽上传区（多文件，PDF/DOCX/TXT/MD ≤50MB），实时显示进度条；上传成功后立即触发解析（后台异步），页面显示"上传成功，后台正在解析…，您可以先保存"。  
Step 3 确认：显示课程摘要 + 加课码大卡片 + 复制按钮 + "跳转到抽取审核工作台"。

**接口**：`POST /api/courses`、`POST /api/courses/{id}/documents/upload`（循环多次）、`PUT /api/courses/{id}`。

### 3.4 课程概览仪表盘 `/courses/:courseId/overview`
**6 大 KPI 卡片**：节点总数、关系总数、班级学生数、班级平均掌握率、本周问答次数、低置信度待审核关系数（可点击跳转审核）。  
**时间线组件**：最近 20 条事件（文档上传完成 / 抽取开始&结束 / 学生加课 / 学生掌握新知识点）。  
**图谱小地图**：AntV G6 小尺寸只读预览，可点击跳转到编辑页。

**接口**：`GET /api/courses/{id}`、`GET /api/courses/{id}/graph`、`GET /api/courses/{id}/learning-path/{uid}/progress`（可传占位 uid 获取全班汇总的后端统计）。

### 3.5 文档管理 `/courses/:courseId/documents`
表格列：勾选框、标题、文件名、类型、大小、页数、分段数、**状态 Pill**（uploaded/parsing/parsed/extracting/completed/failed 六色 Pill）、上传时间、操作。  
操作列：`重新解析`（仅 parsed 之后可用）、`触发抽取`、`任务详情`（Drawer 展示 Celery task 进度、日志最后 50 行、失败原因 & 重试按钮）、`下载原始文件`、`删除`。  
右上角：上传按钮 + 批量触发抽取 + 批量删除。

**接口**：`GET /api/courses/{id}/documents`、`POST /api/courses/{id}/documents/upload`、`POST /api/courses/{id}/documents/{did}/parse`、`GET /api/documents/tasks/{tid}`、`DELETE /api/courses/{id}/documents/{did}`、`POST /api/courses/{id}/extraction/trigger`。

### 3.6 抽取审核工作台 `/courses/:courseId/extraction`（核心教师端页面）
这是教师端与学生端最大的差异点，**重点设计**。

#### 3.6.1 三段式布局
```
┌─────────────────────────────────────────────────────────────┐
│ 顶部工具栏：抽取进度总览（✅已确认／⚠️待审核／❌已拒绝） 3 个徽章 │
│         筛选器：来源文档/节点类型/置信度区间/仅待审           │
│         操作：批量确认 / 批量删除 / 一键重新抽取（增强 Prompt） │
├──────────────────┬──────────────────┬────────────────────────┤
│ 待审核节点表格   │ 待审核关系表格   │  G6 图谱联动预览        │
│ （分页 20）      │ （分页 20）      │  选中行高亮对应节点     │
│                  │                  │  节点可直接在侧图编辑   │
└──────────────────┴──────────────────┴────────────────────────┘
```

#### 3.6.2 待审核节点表格列
| 列 | 说明 | 操作 |
|---|---|---|
| 选中框 | 批量用 | |
| 名称 | 可 inline 编辑（铅笔图标） | |
| 类型 | 枚举 Select（概念/定理/公式/算法/实例/其他） | |
| 描述 | 最多展示 60 字，点击进入详情 Drawer | |
| 来源文档 | Chip，hover 显示 "第 X 页" | |
| 置信度 | 色阶条（绿≥0.9、黄≥0.7、红<0.7） | |
| 操作 | **通过 / 编辑后通过 / 删除** |

#### 3.6.3 待审核关系表格列
| 列 | 说明 |
|---|---|
| 选中框 | - |
| 源节点 → 目标节点 | 两个 Chip，中间箭头，点击各自弹出详情 |
| 关系类型 | Select（包含/前置知识/相关概念/应用/对比） |
| 置信度 | 色阶条 |
| 操作 | 通过 / 翻转方向 / 删除 |

#### 3.6.4 审核状态机（节点/关系都类似）
```
  ┌──auto_extracted──┐（LLM 刚吐出，confidence<0.7）
  │   pending_review  │
  └────────┬──────────┘
           │ 教师点通过/批量通过
           ▼
      confirmed（is_auto=true/false 均可）
           │ 教师编辑后保存
           ▼
      manually_edited（自动记录 edited_by=user_id, edited_at）
           │ 删除
           ▼
       discarded（软删除：保留记录 30 天供审计）
```

**接口**：`GET /api/courses/{id}/extraction/result`（返回 nodes/relations + 审核过滤参数）、`POST /api/courses/{id}/nodes`（手动新增）、`PUT /api/courses/{id}/nodes/{nid}`、`DELETE /api/courses/{id}/nodes/{nid}`、`POST /api/courses/{id}/relations`、`DELETE /api/courses/{id}/relations/{rid}`、`POST /api/courses/{id}/extraction/trigger`（re-extract 增强 Prompt 二轮）。

### 3.7 图谱编辑器 `/courses/:courseId/graph-editor`
基于 §12.6 AntV G6 核心配置，加上教师编辑行为：

#### 3.7.1 自定义工具栏（画布顶部）
`[布局切换:力导向/Dagre] [FitView] [缩-] [放+] [全屏] | [+新增节点] [+连线] [批量改类型] [批量删除] | [撤销] [重做] [导出 PNG] [导出 JSON]`

#### 3.7.2 节点 / 边选中态面板（画布右侧抽屉）
选中节点时展示字段：名称、类型、描述、来源文档、来源页码、是否自动抽取、创建者、创建时间。**所有字段可直接修改**，失焦即调用 `PUT /nodes/{nid}`。

#### 3.7.3 关键交互
- 空白处双击 → 弹出"新增节点"Modal（类型默认"概念"）。
- 选中节点 A → 按住 Shift 拖到节点 B → 弹出"新增关系"Modal（默认 relation_type=相关概念）。
- Delete 键 → 二次确认 → 删除选中节点/边。
- Ctrl+Z / Ctrl+Y → 撤销 / 重做（最多 20 步历史栈）。
- 画布悬浮工具栏：选中节点出现三个图标：`✎编辑 / 🔗快速连线 / 🗑删除`。

#### 3.7.4 导出能力
调用 `GET /api/courses/{id}/graph/export`，支持 JSON（含节点+关系三元组）/PNG（前端 html2canvas 生成）/GraphML（后续可扩展）。

**接口**：`GET /api/courses/{id}/graph`、`GET /api/courses/{id}/nodes/{nid}`、`PUT /api/courses/{id}/nodes/{nid}`、`DELETE ...`、`POST /nodes`、`POST /relations`、`DELETE /relations/{rid}`、`GET /graph/export`。

### 3.8 问答管理 `/courses/:courseId/qa-admin`
双 Tab：**历史对话**（学生 / 时间 / 问题 / 回答摘要 / 是否用了 LLM / 引用节点数）、**反馈工单**（学生点"答非所问/不够详细"产生的工单，支持状态：新/处理中/已解决）。  
动作：`查看对话详情` Drawer（显示上下文 + 引用节点跳转图谱）、`标记已处理`、`回复学生`（可选：将修正后的内容作为一段备注写回该问答记录）。

**接口**：`GET /api/courses/{id}/qa/history`（教师端返回全班所有历史）、`POST /api/qa/{qid}/feedback`（读）。

### 3.9 学生进度管理 `/courses/:courseId/students`
三区块：
1. **概览卡片行**：总人数 / 平均掌握率 / 活跃学生数 / 本周学习人次
2. **学生列表表格**：学号、姓名、邮箱、加入时间、掌握节点数 / 总数（Mini 进度条）、最近学习时间、操作（`查看详情` Drawer / `重置进度`）
3. **班级薄弱点 Top 10**：条形图（x 轴掌握率、y 轴知识点），点击某条形 → 跳图谱编辑器并高亮该节点
4. **导出按钮**：CSV（全班掌握矩阵：行=学生，列=知识点，值=0/1）

**接口**：`GET /api/courses/{id}/learning-path/{uid}/progress`（循环 uid 或新增后端全班统计接口）、`POST /api/courses/{id}/learning-path/progress`（教师端可手动修正）。

### 3.10 课程设置 `/courses/:courseId/settings`
Tab 1 基本信息：名称、描述、封面上传、类别、学期。  
Tab 2 加课邀请：`course_code` 大号展示 + 复制按钮 + "学生端加课链接"（`/join?code=XXXX`）+ 🔄 重置加课码（二次确认：原码失效）。  
Tab 3 抽取策略开关：①自动审核（confidence ≥ 0.9 自动通过）②增强抽取轮次（1/2）③默认关系类型。  
Tab 4 危险操作：归档课程 / 彻底删除课程（"删除后无法恢复，所有学生数据将一并清理"）。

**接口**：`PUT /api/courses/{id}`、`DELETE /api/courses/{id}`、`POST /api/courses/{id}/join`（只读）、`GET /api/users/{uid}/profile`（当前用户）。

## 6. 抽取审核工作台：状态机 & 交互细节

### 6.1 表格与图谱联动
- 点击待审核节点表格行 → G6 `graph.findById(id).setState('selected', true)`，其余取消；画布居中（`graph.focusItem(id)`）。
- 选中多个行 → 批量高亮；"批量通过"按钮调用后端批量接口或前端循环 Promise.all 调 PUT。
- 选中待审关系行 → 同时高亮 source、target + 对应 edge。

### 6.2 批量确认后的 Undo
批量确认后顶部出 5 秒 toast：「已通过 12 个节点 · **撤销**」。实现方式：在 `extraction.ts` 里记录最近一次批量操作的 id 列表，点击撤销时循环调 DELETE 恢复 pending。

### 6.3 重新抽取（增强 Prompt）
工具栏"🔁 重新抽取当前文档"按钮会：
1. 调用 `POST /api/courses/{id}/extraction/trigger`，传 `enhanced: true`；
2. 返回 tid → `documents.ts` 监听任务；
3. 任务完成后自动刷新 ExtractionView，并在左侧列表标记新条目（徽章 `NEW`）。

## 7. AntV G6 教师编辑模式

### 7.1 编辑模式 vs 学生只读模式开关
同一组件 `components/graph/GraphCanvas.vue` 接收一个 `mode: 'read' | 'edit'` prop：
- `read`：无悬浮工具栏、Shift 拖动禁用、删除键拦截；
- `edit`：启用所有编辑交互，选中态面板可编辑字段。

### 7.2 离线保存冲突
多人同时编辑同一门课程时：`PUT /nodes/{nid}` 后端返回 409 Conflict 时，前端 toast "该节点已被其他教师更新，即将刷新"，然后调用 `graphStore.loadGraph()` 重新拉取。

### 7.3 Undo/Redo 栈结构
```ts
type HistoryFrame = {
  kind: 'node_add'|'node_del'|'node_edit'|'edge_add'|'edge_del'|'edge_edit'
  before?: Partial<GraphNode|GraphEdge>  // edit/del 用
  after?:  Partial<GraphNode|GraphEdge>  // add/edit 用
  id: string
}
```
每次写操作成功（后端 200）后 push 一帧到 `history`，清空 `redoStack`；undo 按反向 API 调用。

## 8. 异常 & 边界场景处理

| 场景 | 前端表现 | 后端配合 |
|---|---|---|
| 登录态过期（401） | 自动退出 → Login + 登录后跳回原页 | 后端返回 401 {detail: "expired"} |
| 权限不足（403） | Toast 红色 "无课程管理权限"；若是非 owner 尝试写操作，按钮本身 disabled | 后端 403 |
| LLM 限流导致抽取失败 | 任务详情 Drawer 显示"LLM 限流，建议 2 分钟后重试"+ 重试按钮 | 后端记录 429/5xx 到任务日志 |
| 上传文件超 50MB | 前端拦截，提示"请选择 ≤50MB 的文档"，不发请求 | 后端再校验 |
| 图谱为空（没上传过文档） | G6 画布显示空状态插画 + 按钮 "上传第一份文档" → 跳到 documents | |
| 学生数为 0 的课程 | Progress 页面显示 "还没有学生，复制加课码分享给学生吧" + 大号 course_code 卡片 | |
| 删除课程 | 前端二次确认弹框，输入课程名二次匹配后再真删 | 后端 CASCADE 删 |
| 抽取 0 结果（空文档） | Task Drawer 红字"无法识别出实体"，按钮"手动创建首个节点" → 弹新增节点 Modal | 后端返回 nodes=0 的正常响应 |

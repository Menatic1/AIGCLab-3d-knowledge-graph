## 一、S2A 目标与服务模型

### 1.1 项目目标

**背景引入**（参考 S2A 开篇的"问题引入"写法，用 2~3 段铺垫痛点）：
- 高校课程知识体系庞大，知识点分散在各章节目录中，学生缺乏整体结构认知；
- 教师人工绘制课程知识图谱成本高、维护难，难以随教学内容迭代；
- 学生课业答疑依赖教师/助教，缺乏 7×24 的智能答疑与个性化路径指引。

**设计目标**（参考示例的"1）2）3）"编号式目标，逐条展开）：

1）**降低知识图谱构建门槛**——教师上传 PDF/Word/PPT 课程材料，系统自动解析并以大模型抽取知识点与关系，支持 AIGC 一键生成图谱草稿，将建图成本从"逐节点手工绘制"降为"上传材料 + 校对修正"。
2）**提升学习导航效率**——以知识图谱为核心承载课程知识结构，提供智能问答、学习路径推荐、掌握进度追踪，帮助学生"按图索骥"高效学习。
3）**增强学习体验**——3D 校园模型与可视化图谱、多模态学习资料、教师/学生双角色界面（教师端绿色系、学生端蓝紫系）、访客中心导览，兼顾功能性与易用性。

### 1.2 服务模型

**2.1 产品架构**
- **2.1.1 通信流程**（附图：通信流程图）：B/S 架构、前后端分离；前端 Vite 开发服务器 → 后端 FastAPI；HTTP/JSON 通信；JWT 令牌鉴权与角色判定；教师端/学生端权限隔离。
- **2.1.2 功能架构**（附图：产品功能图，可直接复用已有功能路径图）：按"注册前 / 教师端 / 学生端"三区展示功能归属。

**2.2 技术框架**
- **2.2.1 系统技术框架**（附图：系统技术框架图）：前端 React 18 + Vite 5 + TypeScript + AntV G6（图谱引擎）；后端 FastAPI + SQLite + JWT RBAC；AI 侧接入大模型 API（知识抽取 / AIGC 生成 / RAG 问答）。
- **2.2.2 知识图谱与 AI 处理框架**（附图：知识抽取与问答链路图）：文档解析 → 中文分词（jieba + 2-gram 兜底）→ LLM 知识点抽取 → 关系类型映射（包含/先修/关联）→ 图谱入库；RAG 检索增强问答链路。

## 二、S2B 组织管理与业务分析方案

### 2.1 项目组织安排

- **1.1 人员安排**（附图：团队分工图，5 人配置）：
  1）**项目总负责人兼产品经理（1 人）**——统筹协调项目全局，把握产品整体走向；负责背景调查、可行性分析、业务需求分析与功能设计文档，完成产品原型与功能框架设计；
  2）**前端开发（1 人）**——负责前端页面开发与图谱可视化交互（AntV G6 2D/3D 渲染、手绘风格界面），对接后端接口，完成功能联调与界面测试；
  3）**后端开发（1 人）**——负责后端接口开发、数据模型设计、JWT 权限体系与 RBAC 隔离，主导文档解析、知识抽取等 AI 链路的服务端集成与性能优化；
  4）**科研助理（1 人，播音专业）**——负责行业调研与资料收集、汇报文案与说明文档撰写、演示视频录制与配音讲解、答辩材料的美化与宣讲呈现，发挥播音专业的表达与展示优势；
  5）**AI 算法工程师（1 人）**——负责大模型提示词工程、知识抽取链路设计（jieba 分词 + LLM 抽取）、RAG 智能问答与 AIGC 图谱生成的技术实现，以及抽取准确率的评测与调优。

## 三、S2C 技术路线及实现方案（篇幅最大的核心文档）

### 3.1 技术路线

**1.1 技术概述**
- **1.1.1 前端技术栈分析**：Vite 5 + React 18 + TypeScript（模块化组件结构）；AntV G6 图谱渲染（Canvas2D，g-plugin-rough-canvas-renderer 手绘风格）；three.js + react-force-graph-3d（3D 校园模型）；各依赖版本选型与锁定理由（参考示例逐依赖分析写法）。
- **1.1.2 后端技术分析**：FastAPI（异步、自动 OpenAPI 文档）、SQLite（轻量单机）、JWT RBAC 三依赖（require_role/require_teacher/require_student）、异步中间件（认证/日志）、jieba 中文分词。
- **1.1.3 AI 技术分析**：大模型 API（知识抽取、AIGC 图谱生成、RAG 问答）、检索增强（课程文档切片 + 向量召回 + 答案引用节点溯源）。
- **1.1.4 测试技术分析**：接口自动化测试、角色权限访问控制测试（教师访问学生接口返回 403）、知识图谱结构校验（节点数/关系数/三类关系占比）。

**1.2 技术框架设计**
- **1.2.1 前端架构分层**（附图：前端分层图）：pages（页面）/ components（组件）/ context（全局状态：TabContext、KnowledgeContext）/ middleware（认证与路由守卫）/ services（API 封装）。
- **1.2.2 后端技术架构**（附图：后端框架图）：路由层 → 依赖注入（RBAC 校验）→ 业务层 → 数据层（模型 15+ 张表：用户/课程/文档/图谱/问答会话等）。

**1.3 技术难点分析**（参考示例 1.3 分点写法，每点写"现象 + 原因 + 解决思路"）：
1）**知识抽取准确性与中文分词**——单字分词导致知识点切分错误，采用 jieba + 2-gram 兜底；
2）**图谱布局与交互性能**——118+ 节点大图布局（charge/distance/collide 参数调优），拖拽事件丢失（改用 window 级 pointer 监听）、点击命中率（透明命中区）；
3）**图谱层级构建与关系方向**——关系类型映射不全导致层级错乱，需统一"包含/先修/关联"方向修正与根节点识别；
4）**RAG 问答引用溯源**——答案与图谱节点关联高亮，需保证检索召回相关性；
5）**前后端一致的权限隔离**——接口级（后端依赖注入）与界面级（前端路由过滤）双重控制。
